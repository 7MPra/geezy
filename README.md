# Geezy

Wii Homebrew用のVJビデオシンセ、0.18.1。Wiiリモコン横持ち・Classic Controller・USB-MIDIパッドで、5つの空間、クローム彫刻、チャージ、ストロボ、2Dグラフィックスを演奏します。音同期とMIDI CC／フェーダー操作は使いません。

## 起動・ビルド

```powershell
./scripts/build.ps1
./scripts/run.ps1
```

Docker Desktopと `devkitpro/devkitppc` を使ってホスト側テストとWiiビルドを実行し、`apps/geezy/boot.dol` を更新します。Dolphinは既定で `D:\Dolphin-x64\Dolphin.exe`。専用プロファイル `.dolphin-prototype` を使い、既存の設定を上書きしません。実機ではSDの `apps/geezy` に `boot.dol` と `meta.xml` を置いてHomebrew Channelから起動します。

## Wiiリモコン（横持ち）

この節は1本使用時の操作です。2本接続時は下の「2本のWiiリモコン」を参照してください。センサーバー不要。方向は横持ち時の上下左右です。Dolphinでは映像ウィンドウにフォーカスを置きます。

| 操作 | リモコン | Dolphinの既定キー |
| --- | --- | --- |
| 2秒チャージ、圧縮、加速ストロボ。離すとドロップ | A | A |
| 2Dグラフィックスを開く。離すと閉じる。押すたび次のパターン | B | B |
| 配色シード更新＋打撃（離した時に確定） | 1 | 1 |
| 造形バンク＋軌道変更＋打撃（離した時に確定） | 2 | 2 |
| タップで方向打撃、ホールドで5倍ブースト | 十字キー | 矢印 |
| 大きく視線を外す。離すと復帰 | B＋十字キー | B＋矢印 |
| 速度ギア0〜3 | ＋／− | E／Q |
| HUD表示切替 | 1＋PLUS | 1＋E |
| 空間テーマ0〜3を巡回 | 2＋PLUS | 2＋E |
| 空間パラダイム0〜4を巡回 | 2＋MINUS | 2＋Q |
| 配色バンク0〜15を巡回 | 1＋MINUS | 1＋Q |
| 全設定リセット | ＋と− | R |
| 終了 | HOME | H |

1/2を使うコマンドは、数字ボタンを先に押すか同時に押します。単押しの色／造形変更は消費されます。シェイクは任意の2.5倍打撃で、ボタンだけで全操作が完結します。

| 同時押し | ↑ | → | ↓ | ← |
| --- | --- | --- | --- | --- |
| 1＋方向：質感 | クローム | グリッド | ゴースト | WIRE＋頂点ドット |
| 2＋方向：配置 | 非対称3体 | 巨大1体・オフセンター | 2体 | 中心＋衛星群 |
| 1＋2＋方向：背景 | 格子＋粒子 | 太いワープトンネル | 全画面ドーム＋格子 | 粒子マトリクス |

1＋2＋斜め方向は梁の選択：↖立体格子、↗矩形ゲート、↘平行ブレード、↙斜材トラス。背景0として呼び出し、梁の選択は保持します。

A＋1は反射模様（ホライゾン／階調／オイルスリック／白黒）、A＋2は造形バンクのみ、Bを保持したまま1は2Dパターンを追加送り、B＋2は軌道のみを巡回。1＋2を方向なしで押し、両方離すとテーマ・配色バンクも含めてリミックスします（ギアとHUD表示は保持）。A/Bは通常コマンド中もチャージ／2Dホールドとして動作します。ただし1＋2＋A/BのマスターFXでは通常動作を消費します。

## Classic Controller

Wiiリモコンに接続し、拡張タイプを毎フレーム検出します。リモコンとUSB-MIDIとの併用も可能です。左スティックは20%デッドゾーン付きの連続操舵＋ブースト。倒し始めだけ打撃を発火します。

| --- | --- |

| ＋／− | ギア |
| ZL／ZR単押し | テーマ巡回／配色16バンク巡回（ZRは離した時に確定） |
| L＋X | 配置巡回 |
| L＋Y | 空間パラダイム0〜4を巡回 |
| R＋Y | 軌道のみ巡回 |
| R＋X | 2.2倍打撃＋カメラ角度スナップ |
| L＋R＋Y | フル・リミックス |
| L＋十字キー（↑→↓←） | マテリアルプリセット0〜3 |
| L＋R＋十字キー | マテリアルプリセット4〜7 |
| R＋十字キー | 2Dパターン0〜3選択（表示はB） |
| Rを保持→ZL＋十字キー | 2Dパターン4〜7選択（表示はB） |

## APC mini USB-MIDI

Wii USBポートへ直接接続します。USB APIはlibogcのAudio/MIDI Streaming Interface（class 1 / subclass 3 / protocol 0）を探索し、同一インターフェースのBulk IN/OUTを使います。USB-MIDI 1.0の4バイトイベントパケットを受信し、ケーブル0のNote On/Offだけを処理します。Note On velocity 0も解放。CC、フェーダー、クロック、SysExは操作へ割り当てません。

| グリッドの段（下から0） | Note | 動作 |
| --- | --- | --- |
| 7左 | 56〜60 | 空間パラダイム0〜4を直接選択。現在のパッドは緑点灯 |
| 7右 | 61／62／63 | テーマ／スキン／反射をそれぞれ巡回 |
| 6 | 48〜55 | Spaceプリセット0〜7 |
| 5 | 40〜47 | Sculptureプリセット0〜7 |
| 4左／右 | 32〜35／36〜39 | 軌道0〜3／ギア0〜3 |
| 2・3 | 16〜31 | 配色16バンク。各4バンクでハーモニー0〜3。同じ選択を再押下すると、そのバンクのシードを微変異 |
| 1 | 8〜15 | 2Dパターン0〜7をホールド。複数押下時は最後のパッドを表示し、離すとまだ押している前のパターンへ戻る |
| 0 | 0／1／2／3 | 左／下／上／右の強打撃とホールドブースト |
| 0 | 4 | チャージ。離すと蓄積量に応じたドロップ |
| 0 | 5 | 2.2倍打撃＋カメラ角度スナップ |
| 0 | 6／7 | リミックス／HUD切替 |

| プリセット | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| マテリアル：テーマ | Dark | White | Fog | Print | Dark | White | Fog | Print |
| マテリアル：スキン | Chrome | Chrome | Chrome | Chrome | WIRE | Ghost | Grid | Chrome |
| マテリアル：反射 | Horizon | Horizon | Horizon | Horizon | Oil | Mono | Horizon | Bands |
| Space：背景/梁 | 0/0 | 1/1 | 2/0 | 0/1 | 0/3 | 3/2 | 1/2 | 2/3 |
| Sculpture：shape/layout | 0/0 | 1/1 | 2/2 | 3/3 | 4/0 | 0/2 | 2/1 | 4/3 |

外周の論理Note64〜67はテーマ、68〜71はギア、82〜89はマスターFXホールド。汎用コントローラー用の72〜75は軌道、76〜79はSpace0〜3、80はリミックス、81はHUDです。

マテリアルプリセットはClassicのL＋方向／L＋R＋方向で選択します。外周64〜67は従来どおりプリセット0〜3。空間パラダイムの変更はテーマ・配色・ギアを保持し、リミックスは空間パラダイムも再選択します。HUDの `WM0`〜`WM4` が現在の空間です。

LED出力はAPC miniとして識別した機器に限定します。LEDは実際の現在値から選択状態を計算し、変更分だけ送信します。初代グリッドは指定の `09 90 note velocity`（指定値の消灯0／選択1／モーメンタリ3・5）。外周の単色LEDは0/1。MK2は機器のProduct文字列にある `mk2` / `mkii` を検出し、グリッドの最大輝度 `0x96` と緑21／黄13／赤5へ変換。MK2外周100〜107／112〜119を論理64〜71／82〜89へ対応させます。MK2は標準のクリップ配列を使用してください。[Akai公式通信仕様](https://cdn.inmusicbrands.com/akai/attachments/APC%20mini%20mk2%20-%20Communication%20Protocol%20-%20v1.0.pdf)

USB初期化・列挙・設定は低優先度LWPワーカーへ隔離し、Bulk転送は非同期。描画スレッドは有限長のイベントキューを読むだけです。切断・転送エラー・キュー溢れでホールドを解除し、LED送信が2秒完了しない時も接続を切り離します。DMAバッファは完了通知まで再利用しません。機器未接続でもリモコン／Classicと描画は継続します。libogcはIOSによりUSB列挙の対応が異なります。[libogc実装](https://github.com/devkitPro/libogc/blob/master/libogc/usb.c)

## Master Kill & Post-FX Deck（0.17.0）

すべて押している間だけ有効です。MIDI・Classic・リモコンのFXはOR合成し、異なる入力元のホールドも併用できます。APC右端は押下中LED=1、解放時0。グリッドNote8〜15は引き続き2Dオーバーレイ専用です。

| APC論理Note | Classic（ZRを保持） | 動作 |
| --- | --- | --- |
| 82 | A | 完全暗転。HUDも消し、残像を無効化 |
| 83 | B | 全画面純白 |
| 84 | X | HUD前の最終画面をフリーズ。内部時間を停止し、空間・配色・造形等の操作は裏で受付 |
| 85 | Y | 左半分を右へ反転した左右対称 |
| 86 | ↑ | 左上象限を4象限へ折り返す万華鏡 |
| 87 | → | 最終画面のネガポジ反転 |
| 88 | ↓ | 40×30セルの最近傍モザイク |
| 89 | ← | 黒白交互の2フレーム周期ストロボ（60Hz出力時30Hz、50Hz出力時25Hz） |

リモコンは **1＋2＋Aでフリーズ、1＋2＋Bで万華鏡**。数字ボタンを先に保持します。FXで使ったボタンは解放まで通常コマンドから除外し、解除時の配色・リミックス誤発火を防ぎます。ClassicのZR単押し配色変更は離す時に確定し、ZR＋FXでは変更しません。従来の2Dパターン4〜7選択は、競合を避け **Rを保持→ZL＋方向** に移しています。

排他優先順位は **暗転 → 白転 → フリーズ → ストロボ → 通常合成**。通常合成では万華鏡が左右ミラーに優先し、モザイク・反転を重ねられます。HUDは通常合成の後で描くため反転やモザイクの影響を受けません。暗転・白転・フリーズ・ストロボではHUDも省きます。

フリーズの最初の可視フレームだけシーンを描き、2Dと合成FX込み・HUD前の画面を専用RGB565テクスチャへ保存します。その後は専用テクスチャの表示のみで、3D提出もEFBテクスチャコピーも0回。保持中に選んだ新しい空間へ、離したフレームで切り替わります。上位の暗転・白転を重ねても保存画は維持します。RGB565保存により色の精度は5/6/5bitです。暗転・白転・ストロボは初回からシーンとEFBテクスチャコピーを省きます（映像出力用コピーは継続）。

ドームは方向と波形係数を起動時にLUT化し、各頂点の三角関数を排除。波形の位相に必要なsin/cosだけを1フレーム各1回計算します。Horizonは基礎・配管・頂点スナップを含むセル境界全体がカメラ背面にある時だけ省略。Quantumも背面の点と両端が背面の線を省き、視点をまたぐ線は保持します。広角時の見切れを避ける保守的な判定であり、常に描画数が半減する保証はありません。

モザイクを含む画面FXの静的クワッドも起動時にディスプレイリストへ格納し、毎フレームの4,800頂点のCPU送信を省きます。追加メモリは640×480時、フリーズ画像約600KiB＋画面リスト約340KiB＋ドームLUT約6KiBです。

## 2本のWiiリモコン（0.18.1）

CHAN 1が接続されると両手縦持ちへ切り替わります。左手＝1P（CHAN 0）、右手＝2P（CHAN 1）。同じ手のコマンドは **B＋A または B＋十字キー** だけです。残りは左右に分けて押します。1本用の1＋2や2＋PLUSなどのコードは両手モードでは使いません。切断すると左手は従来の横持ち操作に戻り、右手のホールドも解除。Classic・APC入力は引き続き併用できます。

| 単独操作 | 左手1P | 右手2P |
| --- | --- | --- |
| A | チャージ／離すとドロップ | 強打撃＋カメラカット |
| B保持 | 2Dステンシル | 万華鏡 |
| ↑／→／↓／← | ステア＋ブースト | 造形／配色／軌道／配置を巡回 |
| 1／2（離した時） | 配色／造形を巡回 | World Mode／Themeを巡回 |
| ＋／− | ギア増減 | ギア増減 |
| HOME | 終了 | 終了 |

両手モードの造形変更は `shape` のみを切り替え、軌道とカメラ目標角度を変更しません。

| 同じ手のBコマンド | 左手1P：背景・グラフィックス | 右手2P：Master FX |
| --- | --- | --- |
| B＋↑ | 立体格子 | 万華鏡 |
| B＋→ | 太いワープトンネル | 左右ミラー |
| B＋↓ | 全画面ドーム | フリーズ |
| B＋← | 斜材トラス | 反転 |
| B＋A | 2Dパターンを次へ | モザイク |

左手Bのステンシルは背景選択中も表示されます。B＋AのAはチャージ／打撃として発火しません。

| 片手で保持 → 反対の手で操作 | ↑ | → | ↓ | ← | A |
| --- | --- | --- | --- | --- | --- |
| 左1 → 右 | 立体格子 | 矩形ゲート | 平行ブレード | 斜材トラス | リミックス |
| 左2 → 右 | クローム | グリッド | ゴースト | ワイヤー | 配色バンクを次へ |
| 右1 → 左 | 格子 | トンネル | ドーム | 粒子マトリクス | HUD切替 |
| 右2 → 左 | ホライゾン反射 | 階調反射 | オイルスリック | 白黒反射 | 2Dパターンを次へ |

左Bを保持し、右1＝暗転／右2＝白転／右＋＝即時ストロボ。いずれもホールド式。両手の−を同時に押すと全設定リセットです。

修飾ボタン（Bまたは反対の手の1・2）を先に押してからコマンドを押します。同時押しも可能。1・2単独の動作は離した時に確定し、コマンドに使った場合は発火しません。Bコマンドを優先し、B保持中は1・2の左右コマンドを実行しません。

FX修飾で使ったキーは離すまで通常操作を消費します。両手シェイクは120ms以内の2本の加速度立ち上がり、または両方のBを保持した状態のシェイクで、リミックス＋3倍打撃。各手に再アームとクールダウンを設け、加速が続くだけでは連発しません。1本だけのシェイクは従来の2.5倍打撃です。

B保持中の `gf.x` は最大±1へ制限し、60Hzで平滑化して追加ロール最大±38°と視線オフセットへ反映します。両手でBを持つ場合は平均し、離す／加速度データが無効になると0へ戻ります。フリーズ中も入力は受け付けますが、姿勢の時間進行は止まります。実際の握り方・センサー応答の調整は実機確認が必要です。

## 多段TEVとハイブリッド空間（0.18.0）

- 64×64・RGB565・REPEATの滑らかな干渉マップを起動時に1度生成。CHROMEは4段TEVで、インダイレクトUV屈折、明部の閾値、配色干渉、黒を保つ乗算と白ハイライト合成を実行します。歪み量はburst・overdrive・tensionに連動します。
- 新しい螺旋／刀身のGRIDスキンは長さ・断面方向のUVを使用し、細い面が一色に潰れるのを防ぎます。GRIDは3段TEV。基本UVに対して逆方向・2.3倍のパルスUVを重ね、交点を4倍で増幅します。Display Listの法線UVにも同じ変換を合成します。
- Darkテーマの残像にもインダイレクト屈折を使用。黒の減算と減衰は維持し、WM3でも残像を利用できます。Theme 3、GHOST、WIRE、チャージ中の白黒表現は専用の従来マテリアルを維持。2D・HUD・Master FXへ移る際は間接参照を解除します。
- libogcの間接行列APIは `GX_SetIndTexMatrix` を使用しています（[公式ヘッダー](https://github.com/devkitPro/libogc/blob/master/gc/ogc/gx.h)）。追加テクスチャは8KiB。ピクセル歪みはGXで処理し、CPUで頂点ごとの歪み計算は行いません。
- 彫刻は14系統。直交配管、二重／三重螺旋と横桟、中空メンガーケージと逆回転コア、180〜540°ひねりのひし形断面メビウス刀身、10〜14節の機械脊椎を追加。螺旋／刀身は既存の32枠キャッシュ、他は箱・梁のリストを再利用します。チャージと網点テーマは従来の頂点スナップ経路です。
- 全空間でgear 3／backdrop 2のドーム、backdrop 1のワープトンネル、ベクトル粒子を共有。WM1は地表・上空の巨大彫刻、WM2は吹き抜けのコア、WM3はWIRE／GHOST彫刻へ整列する粒子、WM4は14系統の彫刻とラティスの重なりを描きます。WM2のlayout 0はメカニカルな4種を優先し、他のlayoutは14種から選びます。
- WM1〜4にもオービット角のバネ、距離、視線、ロール、cutを反映。WM4は正射投影のまま距離に応じて表示範囲を変えます。新レイヤーの彫刻数はWM1/2で最大4体、WM3で1体に制限し、背面を省略します。

今回のビルドでpaired-single行列連結からNaNが再現したため、行列連結はlibogcのC実装を使用します。形状のDisplay Listとキャッシュは維持します。多段TEV・追加レイヤーのGPU負荷は増えるため、実機60fpsを保証する変更ではありません。

## 配色と空間

`Palette` はprimary／secondary／accent／bg_tintの4色。シード由来の色相から、Split-Complementary（150°/210°）、Triadic Acid（120°/240°）、Analogous Twist、Duotone High-Contrastを生成します。16バンクは個別のシードを保持します。クローム上部はprimary、約30%幅の下部反射と側面はsecondary、リムはaccent。地平線の漆黒と純白帯は維持。背景グリッドは3色版を持ち、軸・リング・パネルごとに配り、ワイヤーと粒子はaccentを使います。

- **Dark Cyber**：黒背景、クローム主役、色分けしたグリッド。
- **Whiteout Brutalism**：純白背景と白いGXフォグ。黒とprimaryの梁。
- **Color Fog & Liquid World**：secondary由来の暗いフォグ。背景はクロームへ、主役はaccent単色と黒へ役割交換。
- **Halftone Print**：白地、2〜3色、全3D面に8×8 Bayerの二値網点。平面でも模様が出る位置UVを使用。

8種類の2Dは、黒シャドウ・白い細縁・配色連動の本体を重ねます。単純RGB反転は使いません。

0. 多重C字アーク、破線、目盛りのテックスコープ
1. 斜めブレード＋ヘアライン。左から入り、右へ抜けるワイプ
2. Zバッファで抜く3連パネル窓＋クロスグリッドの額縁
3. Zバッファで抜く円形ポータル＋回転目盛り
4. 現フレームの3D履歴を拡大・回転・RGB並べ替えして貼る二重空間ブレード
5. 高さ130%の巨大ピクセル文字をクロップした網点タイポ
6. 二値網点グラデーション、チェッカー、クロスマトリクスの時間差展開
7. 周囲から中心へ入る8枚のカラ―シャッター

通常の方向打撃や配色変更だけでは2Dは出ません。BまたはMIDIの2Dパッドを押している間だけ展開し、離すとイージングで閉じます。履歴は2D/HUDより前に保存し、装飾を再帰的に取り込みません。Darkテーマでは黒を切り捨てる拡大・回転トレイルを維持。他テーマとチャージ中はトレイルを重ねず、白地やフォグ色を保ちます。RGB色収差は各テーマで使用します。

## 5つの空間パラダイム

| WM | 空間 | 投影・配置 |
| --- | --- | --- |
| 0 | Object-Centric Orbit | 従来の主役群、ラティス、トンネル、ドームと球面オービット |
| 1 | Horizon Landscape | 高度0の飛行視点、最大±70°バンク。ハッシュで高さを決めたビル・三角プリズム・太いパイプが96単位周期で流れる都市地形。backdropまたはlayoutが奇数なら逆さの天井都市も出現 |
| 2 | Brutalist Atrium | 3軸に続く非対称巨壁・多層空中回廊・可動巨柱・光束。アオリ、斜め吹き抜け、壁面並走の建築カメラ。近景の精密リブと遠景の深いフォグでスケール差を作る |
| 3 | Quantum Point-Cloud & Plexus | 2,304点＋近傍結線とWIRE／GHOST彫刻。3軸を循環する波動ベクトル場から、打撃・チャージ・Grid Stepで結晶へ整列。`(shape+layout)%3` が0なら立方格子、1なら二重球殻、2なら立体ドット文字 |
| 4 | Ortho Graphic Slicer | 正射投影。結び目・スライス・多重アーク・ボクセル文字を非対称ゾーンへ配置し、斜めレーンの梁と交差。遠近縮小を使わず、距離に応じて表示範囲が変わる動くポスター |

WM1〜4では中央の `mega()` とオービットカメラを呼びません。操舵と視線オフセットは飛行方向へ、ロールはバンクへ接続。全空間で4テーマ・フォグ・網点・Aの逆位相ストロボと頂点スナップ・2Dステンシル・HUDを共有します。WM3の粒子本体は点と線を維持し、追加の彫刻・背景・トレイルには面も使います。空間変更時は前の空間のトレイルを破棄します。

WM2のlayout 0／1／2／3は巨壁／スカイブリッジ／クラッシャー／光束を主構成として選び、backdropで混在する建築を変えます。cut＋layoutで3つの撮影姿勢を切替。幅15〜30・高さ60・奥行き10〜18の巨壁、階段状の片持ち梁、発光エレベーター、指数イージングするピストンはすべてワールド座標に存在します。カメラ固定の板はありません。近景にだけルーバー・細トラスを追加し、フォグは28〜145単位まで深く重ねます。光束は不透明な細い発光スラブと線束による表現です。

## 保持している3D・運動（WM0）

シード×shapeの14系統（既存9種＋上記5種）：ジャイロトーラス、二重ケージ八面体、スパイク、角フレーム、トーラス結び目、8〜12段のスライス、多軸リング、ボクセル文字、スーパー式多面体。配置は非対称3体／巨大1体／2体／中心と衛星。WIREでは面描画をassertで禁止しています。

主役はローカルアンカーに常駐し、`world_cam` が背景を進めます。背景は3軸モジュロ配置＋端でのフェード。太い多角形トンネルと小ポリゴンのベクトル表示、ギア3または背景2で全方位ドームを維持。カメラは球面オービット、注視先切替、最短角度のバネ（0.55/0.16）、バンク、視線外し、厳密な `radius*tan(fov/2)` 保存のドリーズーム。

物理60Hz、姿勢は通常20fps、チャージ中7.5fps。巡航3/12/36/72 unit/sec、ホールドブースト5倍、打撃600×強度・0.85減衰。Aは2秒で満タン、FOV80→38度、頂点スナップと圧縮。ストロボは6→2tick周期、背景と主役を逆位相の黒白へ。解放は1.2〜4倍打撃とFOV125度。

## 描画の再利用（0.15.0）

- 箱と梁は起動時に単位形状の面／WIREリストを生成し、位置・法線・テクスチャ行列と色を更新して `GX_CallDispList` で描画します。非一様な拡大でも法線は正規化した回転基底を使います。
- トーラス、欠けリング（端面含む）、トーラス結び目は、半径・太さ・巻き数・分割・面／WIREをキーに初回だけローカル形状を生成してリスト化。回転・移動だけで毎フレーム再生成しません。
- 最大32リスト×64KiB（約2MiB）＋単位ボックス4KiBを静的確保。32バイト境界、書込前のCPUキャッシュ無効化、リスト長の検査を行います。同一フレームで使用したリストは上書きせず、前フレーム末の `GX_DrawDone` で退役した領域だけ再利用します。満杯／生成失敗時は従来描画へ戻ります。
- Mode 3の粒子座標・近傍結線・フェードは、描画Pose・シード・形状・配置・結晶化率が変わった時だけ再計算します。通常20fpsの姿勢を60Hz出力する間の重複計算を省き、色や点サイズは引き続き毎フレーム更新します。

チャージ中のワールド頂点スナップとTheme 3の位置依存ディザは従来経路を維持します。八面体のスパイク等の変形形状、粒子の頂点送信、2D、EFBコピーは今回すべてをリスト化したわけではありません。曲面キャッシュの初回生成には従来と同程度の生成コストがかかります。描画リストは状態命令を含めず、TEV・フォグ・カリングを既存の管理に残します。[libogcのディスプレイリスト実装](https://github.com/devkitPro/libogc/blob/master/libogc/gx.c)

CPUの提出負荷を減らす変更であり、GPUの塗りつぶし量やEFB転送は減りません。実機の60fpsや負荷1/10を保証するものではありません。

## 第二段：コピー削減と実機計測（0.16.0）

- Superformula多面体も、対称軸数・鋭さ・面／WIREをキーに既存の32枠へキャッシュします。回転だけのフレームで `powf`・三角関数・法線を再計算せず、周囲の動的な八面体は従来どおり描きます。メッシュ用メモリの追加はありません。
- `history` は色収差またはパターン4の二重空間ワイプが使う時だけコピー。`trail` はDarkテーマ・非チャージだけ更新（0.18からWM3も含む）します。通常の非Darkでは0回、Darkの残像のみなら1回、色収差／ワイプ＋残像で最大2回のEFBテクスチャコピーです。マスクを離した後の閉じるアニメーションも対象です。
- コピー後は `GX_PixModeSync` とテクスチャキャッシュ無効化でGPU内の読み書きを順序付け、途中のCPU `GX_DrawDone` 待ちを取り除きます。最後の画面出力コピー完了は `GX_DrawDone` で待ち、描画リストの再利用と次の画面の提示を保護します。[libogcの同期API](https://github.com/devkitPro/libogc/blob/master/gc/ogc/gx.h)
- 粒子の転送方式は0.15.0を維持しています。実験した共有頂点配列／粒子リストは空間切替後の画素比較に不一致があり、不採用です。頂点スナップ・位置依存網点の既存フォールバックと、曲面の初回生成コストも残ります。

実機を用意したら、次のコマンドで通常版と計測版を生成できます。

```powershell
./scripts/build.ps1 -Profile
```

通常版は `apps/geezy/boot.dol`、計測版はルートの `geezy-profile.dol`。計測版をHomebrewアプリの `boot.dol` として起動すると、既存HUDに60フレームごとの集計を追加します。HUDの表示トグルも共通です。通常版には計測処理・追加表示を入れません。

| 表示 | 意味 |
| --- | --- |
| HZ | VSync待ちも含めたメインループの平均更新頻度 |
| CPU | 入力から描画コマンド提出までの平均時間（ms）。FIFOが詰まった際の待ちも含む |
| IN / 3D / FX / UI | 入力・配色生成、3D提出、色収差・EFBコピー、2D・HUD提出の各平均時間（ms）。背景トレイルは3D区間に含む |
| WAIT | 最後の画面コピー提出＋GPU完了待ちの平均時間（ms）。GPUはCPUと並行動作するため、GPU全処理時間ではない |
| WORK MAX | VSync待ちを除く処理時間の60フレーム内最大値（ms）。形状切替の初回負荷も含む |
| EFB | 1フレーム当たりの平均テクスチャコピー回数。画面出力コピーは含めない |

Dolphinの第二段専用124条件（連続2フレームの合成60条件＋曲面64条件）では、提出時間の平均が第一段8,173µs→第二段5,386µsでした。キャッシュを温めた同一条件の比較であり、実機FPSやすべての場面での短縮率を示すものではありません。

## 検証

```powershell
./scripts/build.ps1
./scripts/check-render.ps1
./scripts/check-render.ps1 -Graphics
./scripts/check-render.ps1 -Stencil
./scripts/check-render.ps1 -Checker
./scripts/check-render.ps1 -Trail
./scripts/check-render.ps1 -Worlds
./scripts/check-render.ps1 -Gpu
./scripts/check-render.ps1 -Master
./scripts/check-render.ps1 -Worlds -Profile
```

ホストのassertテストで入力の押し分け、16バンク、4ハーモニー、Classic操舵、USB記述子の境界検査、Note/CC分離、MK2変換、複数ホールド、カメラ・幾何・ワールド周期を検証します。`-Graphics` は8パターン×4テーマをMIDIイベント経由で巡回。`-Stencil` は中央が元の青い映像のままで外側だけ覆われることを検査。`-Checker` は新しい網点マトリクスの連続動作、`-Trail` は残像が完全な黒に戻ることを確認します。`-Sculptures` は14系統×4スキン、`-Lattice -Beams 0..3` は背景だけの連続移動を検査します。専用Dolphinプロファイル `.dolphin-check` を使用し、キーやフォーカスを操作せず `artifacts/` に画像を保存します。

`-Worlds` は5空間×4テーマ、操舵、チャージ／解放、ステンシルを巡回し、診断用の隅の色コードから20組すべての描画と進行を検査します。`world_test.c` で粒子数、96単位の循環、結晶格子・球殻・文字の座標範囲と有限性を検査。非RVLのUSBスタブもホストテストで呼び出します。

`-Gpu` は404条件をRGB565 EFBコピーで比較します。元の104条件（4プリミティブ×4スキン×4テーマ、頂点スナップ16条件、5世界×4テーマ、40形状同時のキャッシュ超過4条件）は直接描画との比較を維持。追加の172条件は第一段との比較で、粒子の結晶化・ストロボ48条件、5世界×4テーマ×3合成状態の連続2フレーム60条件、Superformula形状×4スキン×4テーマ64条件です。比較用バッファを履歴／残像から分離し、再帰描画の中身を壊さず検証します。さらにドーム・Horizon・Quantumのカリング／LUT比較48条件を追加し、計324条件に加え、新造形5種×4スキン×4テーマの80条件を直接描画と比較。404条件通過、最大平均差0.004/255、大きな差は最大16画素でした。空画像の誤合格も検出し、許容差は平均1.5/255以下、RGB合計差48超の画素が1%以下です。診断プロファイルでRAMへのEFBコピーを有効にし、遅延コピーを無効にします（[Dolphin公式設定定義](https://github.com/dolphin-emu/dolphin/blob/master/Source/Core/Core/Config/GraphicsSettings.cpp)）。`render_test.c` でコピー判定の境界と計測集計も検査します。

Dolphinでの104条件の計測例：キャッシュを温めた描画提出時間の平均は従来3,486µs→最適化1,351µs。最大の画素平均誤差は0.001/255、大きな差の画素は最大2画素でした。これはDolphin内タイマで測る固定テストの値で、実機FPSやライブ全体の倍率ではありません。EFBコピー・入力・2Dは計測区間外です。診断DOLは `geezy-check.dol`、結果画面は `artifacts/gpu-*.png` に保存されます。

`-Master` は16通りのミラー／万華鏡／モザイク／反転を全画素比較し、キル優先順位・2フレームストロボ・フリーズ保持中のシーン提出／EFBコピー0回・裏仕込み後の再開も検査します。`master_test.c` は入力の押し分け・LED・全256マスク×保存状態のコピー判定・時間停止・カリング境界・LUT波形を検査します。

`hybrid_test.c` は右手ボタン／全FX割当、解放時の通常コマンド抑制、切断、両手シェイクの窓・再アーム、傾きの復帰、メビウス環の継ぎ目、螺旋座標を検査します。

Wii実機のUSB列挙・2本リモコンの接続と加速度・APC初代/MK2の実入力とLED・Classic実機・実機FPSは未確認です。USBパススルーの実機検証には接続機器が必要です。Dolphinの映像ウィンドウを出力アスペクト比に合わせると円形パターンが正円になります。映像モードは本体設定に従います。
